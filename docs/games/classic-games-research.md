# 게임방에 고전 게임 얹기 — 조사 보고 (2026-09-23)

질문: "보글보블·철권 같은 유명 고전 게임을 GHC 게임방에서 방 참가자끼리 2P 멀티로 하고 싶다.
내부용이니까 대부분 쓸 수 있는 것 아닌가?"

결론부터: **기술은 전부 가능하다. 막히는 건 거의 전부 저작권이고, "내부용"은 면책이 아니다.**
다만 우회가 아니라 **정공법으로 같은 목적에 도달하는 길이 4가지** 있다.

---

## 1. 전제 교정 — "내부용이라 괜찮다"는 성립하지 않는다

| 근거 | 내용 |
|---|---|
| 저작권법 제30조 | 사적이용 복제는 **"영리를 목적으로 하지 않고 개인적으로 이용하거나 가정 및 이에 준하는 한정된 범위"** 뿐이다. 회사 동료 집단은 "가정에 준하는 범위"가 아니고, 회사는 영리 조직이다. |
| 복제 + 공중송신 | 서버에 ROM/ISO를 올려 여러 계정이 내려받거나 스트리밍하면 복제에 **전송(공중송신)** 까지 더해진다. 사적복제 예외는 애초에 적용 대상이 아니다. |
| 대상 IP의 성격 | 보글보블=Taito(스퀘어에닉스), 철권=반다이남코. **둘 다 지금도 현역으로 파는 상품**(아케이드 아카이브, 철권 8). 권리자가 사라진 사장 IP가 아니라 가장 리스크가 큰 부류다. |
| 실질 위험 | "몰래 쓰다 걸린다"보다, **자가호스팅 서버에 올려 두면 외부 노출·퇴사자 계정·로그로 증거가 영구히 남는다**는 게 진짜 문제다. |

**반대로 에뮬레이터 기술 자체는 합법이다** (Sega v. Accolade, Sony v. Connectix 계보 — 클린룸 재구현은
저작권 침해가 아님). 문제는 언제나 **게임 데이터(ROM)** 쪽이다. 그래서 아래 경로들은
"에뮬레이터는 쓰되 데이터를 합법적인 것으로 바꾸거나, 데이터를 우리 서버에 두지 않는" 방향이다.

> 부수 메모: 우리가 방금 만든 "테트리스"도 **이름이 The Tetris Company 상표**다. 룰(아이디어)은
> 보호되지 않지만 이름·고유 디자인은 보호된다. 내부용이면 실질 리스크는 낮고, **외부 공개
> 계획이 생기면 이름만 바꾸면 된다**(예: "블록 러시").

## 2. 경로 A — 직접 만든다 (지금 사천성·테트리스가 가는 길)

- **안전도**: 100%. **통합도**: 최고 — 카메라·전적·방 로그·관전이 전부 그대로 붙는다.
- **비용**: 게임당 개발 라운드 1~2회.

우리 스택(서버 권위 or 클라 시뮬 + 서버 중재)에 잘 맞고 "고전 감성"이 나오는 후보:

| 후보 | 재활용 | 난이도 | 방 분위기 |
|---|---|---|---|
| **낙하 퍼즐(뿌요·컬럼스형)** | 테트리스 엔진 ~80% | 낮음 | 연쇄 손맛이 제일 좋음 |
| **봄버맨형 4인 난투** | 그리드·타이머·공격 개념 | 중간 | **4인 방에 가장 잘 맞음** |
| **버블 슈터(퍼즐보블형)** | 사천성 보드·연출 | 낮음 | 캐주얼, 관전 재밌음 |
| **탱크(배틀시티형)** | 신규 | 중간 | 2P 협동이 자연스러움 |
| **스네이크 배틀 / 지렁이형** | 신규(단순) | 낮음 | 인원수 자유 |
| **부루마블형 보드** | 턴제라 네트워크 쉬움 | 중간 | 카메라 회의실과 궁합 최고 |
| ~~격투(철권형)~~ | — | **매우 높음** | 히트박스·프레임데이터·롤백넷코드까지 필요. 위 후보 대비 10배 |

**버블보블 자체(협동 플랫포머)** 는 물리·적 AI 때문에 위 후보보다 훨씬 비싸다.
"보글보블 느낌"만 원하면 버블 슈터 쪽이 훨씬 가성비가 좋다.

## 3. 경로 B — 브라우저 에뮬레이터 + **합법적으로 배포 가능한** 타이틀만

- **EmulatorJS** — RetroArch/libretro를 Emscripten으로 WASM 빌드한 오픈소스 웹 에뮬레이터.
  NES/SNES/MD/아케이드/PS1 등. **자가호스팅 가능**.
  넷플레이는 **별도 서버**(`EmulatorJS-Netplay`)를 띄워야 하고, 방식은
  "**호스트 1명이 에뮬을 돌리고 2P 이상에게는 영상을 스트리밍 + 입력을 받는다**".
  → 2인 협동·턴제·파티 게임에 적합. **격투 게임에는 지연 때문에 부족**하다.
- **js-dos (v8)** — DOSBox/DOSBox-X WASM. **IPX 네트워킹**을 WebRTC로 지원해서
  둠 데스매치 같은 진짜 LAN 멀티가 된다. IPX 백엔드도 자가호스팅 가능.

**여기에 합법적으로 넣을 수 있는 것**:
- 둠 셰어웨어(에피소드 1), 울펜슈타인 3D 셰어웨어 — **자유 배포가 허락된 배포본**
- 퀘이크 계열 오픈소스 엔진 + 자유 데이터
- 홈브류 NES/SNES 씬 (상당수가 무료·오픈 라이선스)
- 퍼블릭 도메인 / CC 라이선스 게임, itch.io의 MIT·free 웹게임

**넣으면 안 되는 것**: 보글보블·철권·슈퍼마리오 등 상용 ROM 일체.

## 4. 경로 C — **호스트가 실제로 게임을 돌리고, 화면만 스트리밍 + 입력만 원격** ⭐

우리가 "철권을 같이 한다"에 **가장 빨리, 가장 적은 코드로** 도달하는 길이고,
**GHC에 이미 절반이 들어 있다.**

```
[방장 PC]  실제 게임(에뮬/스팀/콘솔 리모트) 실행
   │  ① 창 캡처  ──WebRTC 트랙──▶ LiveKit ──▶ 방 참가자 화면
   │  ② 가상 입력 주입 ◀──socket `pad:input`──  2P 담당자의 키/패드
```

- **① 화면**: 데스크탑 셸이 ScreenCaptureKit으로 창을 캡처해 송출하는 기능이 **이미 라이브**다.
  다만 지금 경로는 `FFmpeg → RTMP → LiveKit Ingress → 트랜스코딩`이라 **지연이 초 단위**다.
  게임에는 절대 못 쓴다. → 인터랙티브용으로는 **renderer의 `desktopCapturer` 트랙을
  LiveKit에 직접 publish** 하는 저지연 경로를 따로 내야 한다(사내망 기준 **100~200ms** 기대).
- **② 입력**: 신규. 소켓 `pad:input` 릴레이 → Electron main에서 가상 입력 주입
  (macOS `CGEvent`, 크로스플랫폼은 `nut.js`). **"2P 조작권 넘기기" UI**가 핵심 UX —
  방장이 특정 참가자에게 2P 패드를 배정하고, 언제든 회수.
- **지연 현실**: 보글보블·퍼즐·레이싱·턴제는 충분히 할 만하다. **철권 같은 대전 격투는
  100ms대에서도 고수에겐 불편**하다(프레임 단위 게임이라). 가능은 하되 기대치를 낮춰야 한다.
- **법적 위치**: 호스트가 **정식 소유한** 게임을 자기 PC에서 돌리고 화면을 보여 주는 것은
  게임 실황/함께보기에 가깝다. 다만 "여러 명이 동시에 조작"은 1인 1카피 라이선스 해석 여지가 있다.
  ROM을 서버에 올리는 것보다는 **훨씬 깨끗하다**.
- **최대 장점**: 게임을 우리가 하나도 구현하지 않아도 되고, **어떤 게임이든 된다**.

## 5. 경로 D — 오픈소스 멀티플레이 게임을 게임방에 임베드

자가호스팅 가능 + 라이선스 자유로운 멀티 게임을 `iframe`/별도 탭으로 붙이고,
GHC는 **방·카메라·음성·전적·관전**만 담당한다.

후보: Hedgewars(웜즈류), Teeworlds, Freeciv-web, BrowserQuest, 오픈소스 클론 다수
(`osgameclones.com`, `awesome-open-source-games` 카탈로그).

- 장점: 개발비 거의 0. 단점: 우리 UI/전적과 겉돈다, 브라우저에서 바로 되는 게 제한적.
